# bio.viz v0.1.0 (Upcoming)

bio.viz is a second chart library beside safety.viz, for comparing groups and relating variables in biomarker data. Every statistical test it shows is computed by R; the library holds no inference code of its own. This first release sets the repository up, measures what running R in the browser costs, and has the first chart, which draws the groups and prints R's test of them.

## What's new

- The library builds and reports its version. `npm run build` writes a script-tag bundle (global `BioViz`) and an ES module bundle to `dist/bio.viz-0.1.0/`, both committed, and `BioViz.version` reads the package version. Nothing is bundled into them: safety.viz and R are loaded beside bio.viz on a page.
- The house machinery from safety.viz is in place: unit tests, browser tests against the committed bundle, requirement matrices with tests named by requirement, an evidence set rebuilt from each test run, and a check that the committed bundle matches the source. Continuous integration runs all of it on every pull request.
- A chart can ask R for a statistic. `BioViz.r.createConnection` makes a connection with one call, `run(name, { data, args })`, which always answers: with what R returned, with a statement that statistics are unavailable and why, or with R's own error message. Two forms sit behind it. Results worked out ahead of time and shipped with the page are answered without loading anything. Otherwise R itself is started in the browser the first time a result is needed, from webR 0.6.0 on its public CDN or from wherever a deployment serves its own copy, and is never part of the bundle. The R functions come from a file of R source the connection is given.
- One rule for printing a p-value. `BioViz.r.formatStatistic` prints it with the method's name and the counts used, labelled exploratory and unadjusted unless an adjustment is named, with no stars and no verdict. Without a method or counts it prints no number and says what is missing; where R declined to compute, it prints R's reason.
- R in the browser, checked and measured. The [R check page](https://jwildfire.github.io/bio.viz/dev/r-check/) runs a Wilcoxon rank-sum test and a log-rank test on two small public tables three ways: with no R attached, from results desktop R worked out ahead of time, and in R started in the browser at the press of a button. It shows each answer from the browser beside desktop R's, in full, with the difference; the two agree to the last digit. It also reports what starting R in a browser costs for three states: a first visit with nothing cached, a reload with the files cached, and a second call with R already running. On the laptop that recorded the page's figures a first visit took 26.2 MB over the network and 3.6 seconds to the first result, a reload took nothing over the network and 2.1 seconds, and a repeated call took 4 milliseconds.
- A gallery, an evidence page and an API reference for every part of the library. The [gallery](https://jwildfire.github.io/bio.viz/dev/gallery/) lists the charts, and says plainly that none is published yet, then the shared parts the charts are built on. Each has an evidence page listing every one of its requirements with the tests named for it, what each test recorded and the screenshots the tests captured, and an API reference. The connection to R is the first: its [evidence page](https://jwildfire.github.io/bio.viz/dev/r-connection/evidence.html) and its [API reference](https://jwildfire.github.io/bio.viz/dev/r-connection/api.html), which documents `createConnection` and `formatStatistic`. An API reference is the module's reference file rendered, and the build fails when that file and the code disagree about what is exported. ([obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355), [#7](https://github.com/jwildfire/bio.viz/issues/7))
- A synthetic study to draw and test on. The made-up biomarker study from gsm.bio (200 participants, 11,472 results over twelve biomarkers and five visits, 200 outcomes) is copied into the repository unchanged and published with the site, with a record of the gsm.bio commit it came from and a checksum for each file; the tests fail if a file no longer matches. ([obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355), [#7](https://github.com/jwildfire/bio.viz/issues/7))
- A variable is written once, and one function turns named variables into one row per participant. `BioViz.core.variable` checks a variable, which is a biomarker at a visit with a value type (`{ measure: 'IL-6', visit: 'Week 4', value: 'change' }`) or a column (`{ col: 'ARM' }`), and refuses a malformed one with a message naming what is wrong. The value types are the result as measured, the baseline, and the change, fold change and percent change from baseline, with the baseline found the way safety.viz's shift plot finds it. `BioViz.core.frame` resolves named variables against the results table, and the participant table when there is one, to one record per participant, ready to draw and to hand to R; a wide table with one row per participant works as it is. Whoever could not be resolved is left out and counted, by reason. It computes no statistics: every test is still R's. ([obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355), [#8](https://github.com/jwildfire/bio.viz/issues/8))
- The first chart: group comparison. `BioViz.groupComparison` draws one biomarker, at chosen visits, across the levels of any category, as boxes, violins or points, with the number in each group beneath, a second grouping by colour, panels by one further variable and a logarithmic scale. It needs only the results table: with a participant table it adds filters and offers participant-level columns to group by, and without one a group comes from a column carried on the results rows. Clicking a box or a point lists its participants, and a row of the list opens safety.viz's participant profile. The chart is built from safety.viz's shared parts, loaded beside bio.viz on the page and not bundled into it. It computes no test: the line under the chart is where R's answer is printed, and with no R attached it says that statistics are unavailable. The boxes' quartiles and the violins' outlines are checked against desktop R. See the [live demo](https://jwildfire.github.io/bio.viz/dev/group-comparison/) on the synthetic study, its [evidence page](https://jwildfire.github.io/bio.viz/dev/group-comparison/evidence.html) and its [API reference](https://jwildfire.github.io/bio.viz/dev/group-comparison/api.html). ([obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355), [#9](https://github.com/jwildfire/bio.viz/issues/9))
- R's test on the group comparison chart. Under each panel the chart now prints a test of the groups it drew, computed by R: a Welch t-test or a Wilcoxon rank-sum test between two groups, a one-way ANOVA or a Kruskal-Wallis test across more, chosen in a new Test control that offers only the tests that fit the number of groups drawn. The result comes with its method and the number in each group, labelled exploratory and unadjusted, with no stars; between two groups the difference in means and its interval are printed with it. A Pairwise comparisons switch adds a table of every pair with its counts and its p-value adjusted across the pairs by Holm's method. R's own warnings and notes are printed with the result, and a group below the minimum size shows R's reason in place of a number. Each panel has a test of its own, on the participants drawn in it, and the line says what the test covers: the filters in force, and that a second grouping by colour is not part of it. A change to a filter, a group or the test clears the line, shows that it is waiting for R, and prints the new answer, never the old one. The chart computes none of this: it chooses which test to ask for and prints what R returns. On the [live demo](https://jwildfire.github.io/bio.viz/dev/group-comparison/) R is started in the browser when the first test is asked for, about 13 MB once, with gsm.bio's statistics functions, and every number it prints is checked against desktop R running the same functions on the same rows. A page can instead ship R's answers for the views it opens on, and a view it has no answer for says that statistics are unavailable rather than showing another view's numbers; the [API reference](https://jwildfire.github.io/bio.viz/dev/group-comparison/api.html#the-statistics-line) gives the exact request and how to write the same key from R. ([obot.roadmap#356](https://github.com/jwildfire/obot.roadmap/issues/356), [#16](https://github.com/jwildfire/bio.viz/issues/16))
- The group comparison chart opens on everything. With no biomarker named it now draws an overview of every biomarker at every visit, the way safety.viz's histogram opens on every measure: a row for each biomarker, in the Biomarker control's order, and in the row a small panel for each visit with the groups and the number in each group. Each biomarker has its own value axis, the same across its visits. Click a biomarker, or press Enter or Space on it, to view it alone with its visits as panels and R's test under each; All Biomarkers at the head of the Biomarker control leads back. The filters, the grouping, the colour, the mark and the scale apply to the overview as they do to one biomarker. The overview prints no test and asks R for nothing, so a page never shows dozens of unadjusted p-values at once, and on the [live demo](https://jwildfire.github.io/bio.viz/dev/group-comparison/) R is not started until a biomarker is opened. It draws at most twelve biomarkers at a time (the setting `overview_limit`), says how many it is showing of how many, and reaches the rest by pages. ([obot.roadmap#356](https://github.com/jwildfire/obot.roadmap/issues/356), [#17](https://github.com/jwildfire/bio.viz/issues/17))
- Two defaults of the group comparison chart changed with it. `start_value: null` used to open the first biomarker by name; it now opens the overview, and a biomarker's name opens that biomarker. `visits: null` used to mean the first visit after the baseline; it now means every visit. A page that wants one biomarker at one visit names both. For a change from baseline, the baseline visit itself is no longer drawn when it is the only baseline visit: every participant's change there is nought.
- A reason R gives is said once. Where R declines to compute a result its reason is now printed as R wrote it, where the line used to say "not computed" twice. `BioViz.r.formatEstimate` and `BioViz.r.formatComparison` join `formatStatistic`: an estimate with its interval, and one comparison from a table of them, printed by the same rules. ([#15](https://github.com/jwildfire/bio.viz/issues/15), [#16](https://github.com/jwildfire/bio.viz/issues/16))
- The second chart: association scatter. `BioViz.associationScatter` draws two variables against one another, one point per participant. Either axis is a biomarker at a visit, as its result or its baseline, change, fold change or percent change, or a participant-level number such as age; points are coloured by a group, panels come from one further variable, and each axis can be logarithmic. Under it R's Pearson or Spearman coefficient is printed with its interval and p-value, for everyone drawn and, with a colour, within each of its levels, with the method and the pairs used, labelled exploratory and unadjusted; Spearman's has no interval in R and none is made up. A fitted line can be drawn over the points: the identity line, y = x, or R's linear fit or smooth with its band, the straight line's slope and intercept printed with their intervals. Every point of a fitted line is R's, from gsm.bio's new `Analyze_Fit`; with no R attached the points and the identity line still draw and the chart says the rest is unavailable. On a logarithmic axis R is given the logarithms, and the line says so. Drag across the points to list the participants in a region, and click a point to open that participant's profile; on a phone, tap Select a region first so a drag selects and does not scroll. Its [live demo](https://jwildfire.github.io/bio.viz/dev/association-scatter/) opens on the pair the synthetic study was planted with, TNF-alpha against IL-10 at Baseline, true correlation 0.6, and its numbers are held to desktop R's within 1 part in 10^8. `BioViz.r.formatGroup` joins the formatters: one group's estimate, interval, count and p-value, by the rules a whole result is held to. ([obot.roadmap#357](https://github.com/jwildfire/obot.roadmap/issues/357), [#26](https://github.com/jwildfire/bio.viz/issues/26))
- The third chart: correlation matrix. `BioViz.correlationMatrix` draws a grid over a set of variables, either several biomarkers at one visit or one biomarker at several visits, each as its result or its baseline, change, fold change or percent change. Below the diagonal a pair is a mark, wider and darker the stronger R's Pearson or Spearman coefficient, a filled blue disc where it is positive and an orange ring where it is negative, so it reads in greyscale; above the diagonal is the coefficient itself. Every cell has its own pair count, because a coefficient is of the participants who have both values: it is in the cell's name, under the grid while the pointer or the keyboard is on the cell, and in a list beneath that downloads as CSV. The grid prints no p-value, by design. A cell with fewer complete pairs than the minimum shows R's reason and no number. Every coefficient is R's, from gsm.bio's `Analyze_CorrelationMatrix`, asked once per grid; with no R attached the grid's frame still draws and the chart says the rest is unavailable. It opens on every biomarker at the first visit, twelve at a time, which fit a phone whole, and says how many it is showing of how many. For six variables or fewer the pairs can be drawn as small scatters. Click a cell, or press Enter on it, to open that pair in the association scatter, in place, with the same R, method and filters, and a button back that returns to the grid as it was without asking R again. Its [live demo](https://jwildfire.github.io/bio.viz/dev/correlation-matrix/) runs on the synthetic study's twelve biomarkers, where the planted pair is the one large mark, and every cell is held to desktop R's within 1 part in 10^8. `BioViz.r.formatPair` joins the formatters: one pair's coefficient, interval and count, with no p-value. ([obot.roadmap#357](https://github.com/jwildfire/obot.roadmap/issues/357), [#27](https://github.com/jwildfire/bio.viz/issues/27))
- Filters that let nobody through. When two filters together let no participant through, the group comparison chart stopped with an error and left the page half cleared. It now draws nothing, asks R for nothing and says `No participant passes the filters.`, in one biomarker and in the overview, as the association scatter and the correlation matrix do, in the same words; loosen a filter and it draws again. ([#29](https://github.com/jwildfire/bio.viz/issues/29))
- The fourth chart: biomarker screen. `BioViz.biomarkerScreen` runs one comparison, chosen once, across every biomarker and draws one row per biomarker: a standardised difference between two groups (Hedges' g, the first group's mean less the second's in pooled standard deviations), or a correlation with one fixed variable, a participant-level number such as age or another biomarker at a visit. Each row has R's estimate and its interval as a dot and a line on one axis without units, with nought marked, and beside it R's p-value twice, unadjusted and adjusted across the rows by Benjamini-Hochberg or Holm, with each row's counts; the caption says how many tests the adjustment covered. Every row is R's, from one call to gsm.bio's `Analyze_Screen`, and each row's p-value is the one the matching single chart prints for that biomarker. The rows are sorted by R's estimate, largest first, by name or by R's adjusted p-value, and paged twenty at a time. A row R could not compute shows R's reason and stays out of the adjustment. With no R attached no rows are drawn and the chart says so. Click a row, or press Enter on it, to open that biomarker in the group comparison, at the same visit and value with the same two groups and Welch's test, or in the association scatter against the same variable, in place, with the same R and filters, and a button back that returns to the rows as they were. Its [live demo](https://jwildfire.github.io/bio.viz/dev/biomarker-screen/) opens on the difference the synthetic study was planted with, where IL-6 is the top row, and every row is held to desktop R's within 1 part in 10^8. The group comparison chart gains the setting `back`, and `BioViz.r.formatScreenRow` joins the formatters. ([obot.roadmap#358](https://github.com/jwildfire/obot.roadmap/issues/358), [#36](https://github.com/jwildfire/bio.viz/issues/36))
- safety.viz from its `dev` branch. bio.viz's copy of safety.viz's bundle is now safety.viz's own `dev`, at a recorded commit, where it had been the kit's unmerged branch. Every chart's filters follow safety.viz's rule, through the kit: a filter given a `start` opens on it and still offers All, where it used to drop All; only `all: false` removes All, and its first value is then the one the chart filters by; and a value the data lacks falls back to All with a warning in the console, where it used to let nobody through. ([#37](https://github.com/jwildfire/bio.viz/issues/37))
- The chart list. `BioViz.portfolio` lists the four charts in safety.viz's portfolio manifest format, version 2, so safety.viz's demo app can list them beside its own charts, in a Biomarkers group, and draw them on the files a study already has. Each entry says the chart's export and title, the two tables it takes (the results from the labs and vitals file, and the participants from the subject-level file, which is optional), and for each column setting the standard column it reads and whether the chart needs it. The participant is read from each file by its own setting, so the two files may call it differently. The site publishes the same list at [`portfolio.json`](https://jwildfire.github.io/bio.viz/dev/portfolio.json). The format is safety.viz's, copied with a record of its commit, and a test validates the list against it and holds every entry to its chart's settings. ([obot.roadmap#366](https://github.com/jwildfire/obot.roadmap/issues/366), [#32](https://github.com/jwildfire/bio.viz/issues/32))
- A site with a dev build. The released site is published at <https://jwildfire.github.io/bio.viz/> and the current `dev` branch at <https://jwildfire.github.io/bio.viz/dev/>. Its home page names the library, its version, and the version reported by the bundle that page loaded.
