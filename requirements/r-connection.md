# r-connection requirements matrix

> Requirement matrix for the bio.viz **connection to R** and the **p-value formatter** (`src/r/`, exported as `BioViz.r`). Written with task [bio.viz#2](https://github.com/jwildfire/bio.viz/issues/2); parent requirement [obot.roadmap#363](https://github.com/jwildfire/obot.roadmap/issues/363), design [353_design.html](https://jwildfire.github.io/obot.roadmap/requirements/design/353_design.html), sections Statistics engine and How a p-value is shown. The interface these rows describe is written out in [`docs/r-connection.md`](../docs/r-connection.md).

## Scope

One call, `run(name, { data, args, dataId })`, that a chart uses to ask R for a statistic, and the three forms behind it: results shipped with the page, R started in the browser the first time it is needed, and R on a server reached through an engine the page supplies ([bio.viz#122](https://github.com/jwildfire/bio.viz/issues/122)). Plus `formatStatistic`, the one place the rules for printing a p-value live, with `formatEstimate` and `formatComparison`, which print an estimate with its interval and one comparison from a result's rows by the same rules ([bio.viz#16](https://github.com/jwildfire/bio.viz/issues/16)). And `formatGroup`, which prints one group's own result from a result's rows, such as a correlation coefficient within one arm, by those rules ([bio.viz#26](https://github.com/jwildfire/bio.viz/issues/26)). And `formatPair`, which prints one pair's coefficient from a correlation matrix's rows with its interval and its count and, by design, no p-value ([bio.viz#27](https://github.com/jwildfire/bio.viz/issues/27)). And `formatScreenRow`, which prints one row of a biomarker screen with its p-value unadjusted and adjusted across the rows, the adjustment named ([bio.viz#36](https://github.com/jwildfire/bio.viz/issues/36)). And `formatLevel`, which prints one level's p-value from the rows of a request by level, a visit's under a picture across visits, unadjusted or adjusted across the levels with the adjustment named ([bio.viz#85](https://github.com/jwildfire/bio.viz/issues/85)).

Also the R check page ([bio.viz#3](https://github.com/jwildfire/bio.viz/issues/3)), which runs the connection against real R and measures what that costs: rows `RCON-CHECK-*` for how the page compares two answers, `RCON-PAGE-*` for what the page shows, and `RCON-LIVE-*` for the browser tests that run it for real.

Out of scope here: any statistic (those are R functions in gsm.bio) and any server: the server form (rows `RCON-SRV-*`) is the connection's side only, and what reaches a server is supplied by the page. The `RCON-LIVE-*` tests need the network, because they load webR and the survival package from their public hosts; every other test of these rows runs against a stub engine or a stand-in for webR, with none.
