# group-comparison requirements matrix

> Requirement matrix for the bio.viz **group comparison** chart (`src/group-comparison.js` and `src/group-comparison/`, exported as `BioViz.groupComparison`). Written with task [bio.viz#9](https://github.com/jwildfire/bio.viz/issues/9), parent requirement [obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355), and extended with task [bio.viz#16](https://github.com/jwildfire/bio.viz/issues/16), parent requirement [obot.roadmap#356](https://github.com/jwildfire/obot.roadmap/issues/356), which prints R's tests on the chart; design [353_design.html](https://jwildfire.github.io/obot.roadmap/requirements/design/353_design.html), sections Core chart types (group comparison), The shared core, How a p-value is shown, Data the charts expect, Repositories, and Risks and open points. The chart's interface is written out in [`docs/group-comparison.md`](../docs/group-comparison.md).

## Scope

bio.viz's first chart. One value across the levels of a category at chosen visits, as boxes, violins or points, with the number in each group beneath; a second grouping by colour, panels by one further variable and a logarithmic scale; controls for all of them; filters when there is participant data; a listing of the participants behind a box or a point; safety.viz's participant profile from a row of it; and a statistics line that prints what R answers.

The chart is built from safety.viz's kit, loaded beside bio.viz on the page and never bundled into it, and its rows come from the core's frame.

The statistics line prints a test of the groups that R computed: the chart chooses which test to ask for (a Welch t-test or a Wilcoxon rank-sum test between two groups, a one-way ANOVA or a Kruskal-Wallis test across more, with pairwise comparisons on request), hands R the rows of each panel through the connection, and prints what gsm.bio's `Analyze_GroupDifference` returns. In the browser, R is given gsm.bio's one statistics file, vendored here with a record of its commit, and what it answers on the gallery's demo is held to what desktop R answers for the same rows.

Out of scope, and absent on purpose: the computation of any statistical test, estimate, interval, p-value or adjustment, and the rule that cuts a continuous variable into groups. Those are R's. What the chart works out itself is description of the values it draws: counts, the quantiles and mean a box is drawn from, and the outline of a violin. Those are held to desktop R on the synthetic study. The chart from R, with the opening view's statistics stored in the page, is gsm.bio's widget ([gsm.bio#9](https://github.com/jwildfire/gsm.bio/issues/9)).

## Requirement IDs

Prefix **GC**, with these areas: **KIT** (safety.viz's bundle, vendored and loaded beside bio.viz), **CFG** (settings), **BOX** and **VIOLIN** (the numbers a mark is drawn from), **DATA** (panels and cells), **CTRL** (what the controls offer and do), **DRAW** (the marks on the page), **FILTER** (with and without participant data), **LIST** (the listing), **PROF** (the participant profile), **STAT** (the statistics line: which test R is asked for, what R is sent, how its answer is printed, R's vendored statistics file and the expected results), **LIFE** (lifecycle), **MOBILE** (a 390-pixel viewport) and **SITE** (gallery, demo and API reference).
