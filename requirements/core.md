# core requirements matrix

> Requirement matrix for the bio.viz **core**: the library's entry point, its two committed bundles, the vendored synthetic study, the site that publishes them, and the two steps every chart shares before anything is drawn. Written with the repository setup ([bio.viz#1](https://github.com/jwildfire/bio.viz/issues/1); parent requirement [obot.roadmap#363](https://github.com/jwildfire/obot.roadmap/issues/363)), extended with the study and the site's gallery, evidence pages and API reference ([bio.viz#7](https://github.com/jwildfire/bio.viz/issues/7)), and with the variable and the one-row-per-participant frame ([bio.viz#8](https://github.com/jwildfire/bio.viz/issues/8)); parent requirement of both [obot.roadmap#355](https://github.com/jwildfire/obot.roadmap/issues/355). Design: [353_design.html](https://jwildfire.github.io/obot.roadmap/requirements/design/353_design.html), sections Repositories, Data the charts expect and The shared core.

## Scope

What a page or a widget can rely on before any chart exists: the bundles are where the build says they are, they report the version they were built from, and nothing else is bundled into them. What every chart's demo and tests run on: the synthetic study, copied from gsm.bio and held to a record of where it came from. What the site shows for every module: a gallery, an evidence page and an API reference. And what every chart does first, in `src/core/` (`BioViz.core`): name a variable one way, and resolve named variables to one row per participant, counting what was left out.

No chart and no statistics are in scope here. Deriving a change from baseline is arithmetic on one participant's own results; nothing here tests, estimates or compares. The one step across participants is the shared cut rule, added with cross-tabulation's requirement ([bio.viz#43](https://github.com/jwildfire/bio.viz/issues/43), [obot.roadmap#359](https://github.com/jwildfire/obot.roadmap/issues/359)): a number cut into groups at its median, tertiles, quartiles or typed points, which describes the values as a median does and is held to desktop R. Each chart and the connection to R gets its own matrix.
